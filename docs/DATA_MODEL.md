# データモデル定義書（Data Model Specification）

出席管理システムでは、SharePoint Online リストをバックエンドのデータストアとして使用します。

---

## 1. リスト構成一覧

| リスト名 | 用途 | レコード数想定 |
| :--- | :--- | :--- |
| `ConferenceAttendees`（カンファレンス参加者マスタ） | 招待者名簿および当日の出席実績を保持 | 数十〜数百件 |
| `ReceptionLogs`（受付ログ：任意/監査用） | スキャンされた全履歴（二重スキャン含む）を記録 | スキャン回数分 |

---

## 2. リスト定義詳細

### リスト1: `ConferenceAttendees`（参加者・出席管理マスタ）

| 列名（内部名） | 表示名 | データ型 | 必須 | 既定値 | 説明 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| `Title` | 社員番号 | 1行テキスト | ○ | なし | ユニークキー（例: `E12345`） |
| `FullName` | 氏名 | 1行テキスト | ○ | なし | 参加者氏名（例: `山田 太郎`） |
| `Department` | 所属部署 | 1行テキスト | - | なし | 所属組織名（例: `技術推進部`） |
| `CardID` | カードID | 1行テキスト | - | なし | 社員証の製造番号（FeliCa IDm または NFC UID） |
| `Status` | 出席状況 | 選択肢 | ○ | `未出席` | 選択肢: `未出席`, `出席`, `欠席` |
| `CheckInTime` | 出席日時 | 日時 | - | なし | 最初に受付成功した日時 |
| `Receptionist` | 受付担当者 | ユーザー/グループ | - | なし | 受付を行った担当者のアカウント |
| `ReceptionDesk` | 受付ブース | 選択肢 | - | なし | 選択肢: `受付1`, `受付2`, `受付3` |
| `Remarks` | 備考 | 複数行テキスト | - | なし | 特別な対応事項・手動変更メモ |

---

### リスト2: `ReceptionLogs`（受付生ログ・監査用 / 任意）
※未登録カードの調査や、万一のトラブルシューティングのために記録するログリストです。

| 列名（内部名） | 表示名 | データ型 | 必須 | 説明 |
| :--- | :--- | :--- | :---: | :--- |
| `Title` | スキャンID | 1行テキスト | ○ | 読み取ったRaw CardID |
| `ScanResult` | 結果 | 選択肢 | ○ | `成功`, `重複スキャン`, `未登録カード`, `エラー` |
| `MatchedEmployee` | 該当社員番号 | 1行テキスト | - | 照合された社員番号 |
| `Timestamp` | スキャン日時 | 日時 | ○ | スキャン実行日時 |
| `Operator` | 受付端末担当 | 1行テキスト | ○ | 実行者の表示名 |

---

## 3. インデックス・パフォーマンス推奨
- `CardID` 列にインデックス（SharePointの「インデックス付きの列」設定）を作成しておくと、データ件数が増えた場合でも `LookUp` 処理が高速に実行されます。
